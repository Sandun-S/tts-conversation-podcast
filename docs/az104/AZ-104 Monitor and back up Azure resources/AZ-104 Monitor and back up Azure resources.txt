</Person1><Person2> "How does Azure back up a VM?"
</Person2><Person1> "Azure VMs are backed up by taking snapshots of the underlying disks at user defined intervals and transferring those snapshots to the Recovery Services vault as per the customer defined policy. The two things to understand are the vault and the snapshot."
</Person1><Person2> "The vault first."
</Person2><Person1> "Azure Backup uses a Recovery Services vault to manage and store backup data. A vault is a storage management entity that gives a simple experience to carry out and monitor backup and restore. You do not deploy or manage storage accounts. All you specify is the vault. Backup data is transferred in the background to Azure Backup storage accounts in a separate fault domain. The vault also acts as a role based access control boundary to allow secure access to the data."
</Person1><Person2> "Snapshots."
</Person2><Person1> "A snapshot is a point in time backup of all disks on the VM. Azure Backup uses a different extension for each OS. On Windows, the VM Snapshot extension, which works with the Volume Shadow Copy Service, VSS, to take a copy of the data on disk and in memory. On Linux, the VM SnapshotLinux extension, where the snapshot is a copy of the disk."
</Person1><Person2> "Consistency levels."
</Person2><Person1> "Three, and this is a favourite topic. Application consistent: the snapshot captures the VM as a whole. It uses VSS writers to capture the content of machine memory and pending I/O operations. For Linux machines you need to write custom pre and post scripts per app to capture application state. You get complete consistency for the VM and all running applications. File system consistent: if VSS fails on Windows or the pre and post scripts fail on Linux, Azure Backup still creates a file system consistent snapshot. During recovery no corruption occurs within the machine, but installed applications need to do their own cleanup during startup to become consistent. Crash consistent: typically occurs if the VM is shut down at the time of backup. No I/O operations or memory contents are captured. This method does not guarantee data consistency for the OS or app."
</Person1><Person2> "Memory trick."
</Person2><Person1> "Application consistent equals memory and pending writes captured, best. File system consistent equals disk structure fine, apps recover on boot. Crash consistent equals like pulling the power plug. Best, middle, weakest: application, file system, crash."
</Person1><Person2> "The policy."
</Person2><Person1> "You define backup frequency and retention. Currently VM backup can be triggered daily or weekly and stored for multiple years. The policy supports two access tiers: the snapshot tier and the vault tier. By using the Enhanced policy you can trigger hourly backups, with the four hour minimum interval we covered. Selective disk backup using the Enhanced policy lets you back up a subset of data disks attached to a VM and restore a subset from instant restore and vault tier. It helps when critical data is on a subset of disks, or when you use a database backup solution and want to back up only the OS disk to reduce cost."
</Person1><Person2> "Snapshot tier."
</Person2><Person1> "All snapshots are stored locally for a maximum of five days, in what is called the snapshot tier. For all operational recoveries it is recommended to restore from snapshots because it is faster. This capability is called instant restore. Vault tier: all snapshots are additionally transferred to the vault for more security and longer retention. At that point the recovery point type changes to snapshot and vault."
</Person1><Person2> "Numbers: five days in the snapshot tier."
</Person2><Person1> "Yes. Instant restore snapshots up to five days, vault for longer."
</Person1><Person2> "The process."
</Person2><Person1> "Step one: for VMs selected for backup, Azure Backup starts a backup job according to the frequency in the policy. Step two: during the first backup, an extension is installed on the VM if the VM is running. Windows gets VM Snapshot; Linux gets VM SnapshotLinux. Step three: after the snapshot is taken, the data is stored locally and transferred to the vault. Step four: the backup is optimised by backing up each VM disk in parallel. Step five: for each disk, Azure Backup reads blocks, identifies and transfers only the changed blocks, the delta, since the previous backup.
