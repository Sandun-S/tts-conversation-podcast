<Person1> "Welcome back to Study Deep Dive. Episode ten: routing, network security, service endpoints and connectivity. Routes and next hops, network security groups, application security groups, service tags, service endpoints and their policies, and the connectivity and load balancing services. This covers questions forty, forty three, sixty five, sixty six, eighty two, eighty six, eighty seven and eighty eight."
</Person1><Person2> "Start with how routing works in Azure."
</Person2><Person1> "Azure creates system routes for every subnet automatically: traffic within the VNet stays in the VNet, traffic to the internet goes out through the default route zero dot zero dot zero dot zero slash zero, and traffic to private ranges not in the VNet is dropped. Peering adds routes for the peer's address space. Gateways add routes learned by BGP. You can override with user defined routes in a route table, associated to subnets. A route table has routes, each with an address prefix, a next hop type, and for virtual appliances a next hop IP address."
</Person1><Person2> "How does Azure choose between routes?"
</Person2><Person1> "Longest prefix match wins first: a slash twenty four beats a slash sixteen for an address inside both. If prefixes are equal, user defined routes beat BGP routes, which beat system routes. So a user defined route for the same prefix as a system route replaces it. Route tables are associated to subnets, many subnets to one table, but one table per subnet. The route table must be in the same region and subscription as its subnets."
</Person1><Person2> "Next hop types. Question forty three."
</Person2><Person1> "Five types. Virtual network gateway, to send traffic to a VPN or ExpressRoute gateway. Virtual network, to route within the VNet address space. Internet, to route to the internet. Virtual appliance, to route to a network virtual appliance, like a firewall, and this is the only next hop type where you must provide an IP address. None, which drops the traffic. Question forty three asked which type requires an IP address, and the answer was virtual appliance. The explanation of the distractors: Internet, virtual network, and virtual network gateway don't need an IP, since they refer to a built in target."
</Person1><Person2> "Question forty, the peered spokes."
</Person2><Person1> "Two virtual networks, spoke east and spoke west, peered. An NVA, fw appliance one, exists. All traffic from spoke east to spoke west must pass through the appliance for inspection. Options: a local network gateway, a route table with custom routes, a service endpoint, IP address reservations, an NSG with a deny rule. The answer: a route table with custom routes. You add a route with the destination address prefix of spoke west and next hop type virtual appliance with the appliance's IP, and associate it with the east subnets. Why the others fail. A local network gateway represents an on premises network in a VPN. A service endpoint gives PaaS access. IP reservations are about public IP addresses. An NSG filters, allowing or denying, but it can't change the path."
</Person1><Person2> "What else is required for it to really work?"
</Person2><Person1> "The NVA's network interface needs IP forwarding enabled, and the operating system inside needs forwarding turned on, and its own firewall rules need to allow the traffic. If the appliance sits in a hub, the peerings need allow forwarded traffic. You usually need a symmetrical return route in the west subnets pointing back to the appliance, otherwise return traffic bypasses the firewall and gets dropped as asymmetric. Many questions in the real exam ask about exactly these requirements."
</Person1><Person2> "Network security groups in detail."
</Person2><Person1> "An NSG is a stateful packet filter, a list of security rules. Each rule has a name, priority from one hundred to four thousand ninety six, source, source port, destination, destination port, protocol, and action allow or deny, in a direction, inbound or outbound. Lower priority numbers are processed first, and once a rule matches, processing stops. Stateful means that if you allow a flow in one direction, the return traffic is automatically allowed. Default rules exist with priorities sixty five thousand and up that you can't delete but can override with lower numbers: inbound allows virtual network to virtual network, allows Azure load balancer probes, denies all else; outbound allows virtual network, allows internet, denies all else."
</Person1><Person2> "Where do NSGs attach?"
</Person2><Person1> "To subnets and to network interfaces. If both, inbound traffic is evaluated by the subnet NSG first, then the NIC NSG. Outbound traffic is evaluated by the NIC NSG first, then the subnet NSG. A packet must be allowed by both. A single NSG can attach to many subnets and NICs. And NSG must be in the same region as what it's attached to."
</Person1><Person2> "Question sixty six, again."
</Person2><Person1> "Priya had Contributor on nsg web zero one, which is associated with nic web zero one. Can she add a rule that blocks a range of incoming source IPs? Yes. Contributor on the NSG includes Microsoft dot Network slash networkSecurityGroups slash securityRules slash write. Rules are child objects of the NSG itself, and the rule takes effect for any NIC the NSG is associated with. She doesn't need any rights on the NIC to change rules on the NSG. But in question sixty five, she can't change the NIC's DNS settings, since the NIC isn't a child. Hold both ideas together: she controls the NSG's contents, not the objects it's associated with."
</Person1><Person2> "Application security groups and service tags."
</Person2><Person1> "An application security group, ASG, is a logical group of network interfaces, such as web servers. You use it as the source or destination in NSG rules, so you write rules by role instead of by IP. All NICs in an ASG must be in the same VNet. A service tag is a named group of IP address prefixes for an Azure service, such as Storage, Sql, AzureKeyVault, AzureActiveDirectory, AzureCloud, Internet, VirtualNetwork, AzureLoadBalancer. Microsoft maintains the prefixes, so rules don't change when the service's addresses change. Tags can be regional, like Storage dot WestEurope."
</Person1><Person2> "Question eighty two."
</Person2><Person1> "Ten VMs in East US, a key vault Vault1, and NSG1 denying all outbound internet traffic. Allow VMs to access Vault1, least privilege, minimal administration. Which destination in the outbound rule? A service tag, AzureKeyVault. An ASG is for grouping your own VMs, not for Azure PaaS endpoints. An IP address range would require ongoing maintenance as Microsoft changes the vault's addresses. You said ASG. The way to avoid the trap: ask, is the destination one of my own VMs or an Azure service? Azure service by name, service tag."
</Person1><Person2> "Service endpoints. Questions eighty six to eighty eight."
</Person2><Person1> "A virtual network service endpoint extends the identity of your subnet to an Azure service, like Storage or Key Vault. Traffic from that subnet to the service goes over the Azure backbone, not the public internet path, and the service's firewall can allow traffic from that specific subnet. The service still has its public IP and public DNS name, no private IP. Enabled per subnet per service. A service endpoint policy adds filtering: it specifies which Azure Storage accounts, by resource, resource group, or subscription, the subnet may reach through the endpoint. This prevents data exfiltration to other accounts."
</Person1><Person2> "Rules for applying a policy."
</Person2><Person1> "The policy and the subnet must be in the same region. The subnet must have the matching service endpoint enabled, Microsoft dot Storage. A policy can be applied to subnets, and without a policy, the endpoint allows access to any storage account that permits it. Policy definitions can reference storage accounts in other regions, with the global endpoint."
</Person1><Person2> "Facts of the questions."
</Person2><Person1> "Three VNets. VNet West in West Europe has Subnet A, no endpoint. VNet Asia in Southeast Asia has Subnet B with the Microsoft dot Storage endpoint. VNet US in South Central US has Subnet C with the Microsoft dot Storage endpoint, and Subnet D with no endpoint. Storage accounts: storagewest01 in West Europe, storageus01 in South Central US, storageasia01 in Southeast Asia. You create StoragePolicy01 in South Central US allowing all storage accounts in the subscription. Question eighty six: can StoragePolicy01 be applied to Subnet C? True: same region, and the subnet has the endpoint. Question eighty seven: only storagewest01 and storageus01 can be accessed from VNet Asia. False: Subnet B has the endpoint and no policy applied, so the policy doesn't affect it, and the subnet can reach storageasia01 too, and all the others. Question eighty eight: only storageus01 can be accessed from VNet US. False: Subnet C is subject to a policy that allows all accounts, and Subnet D has no endpoint at all, so its traffic uses the public endpoint path, and can reach any account allowing it."
</Person1><Person2> "Is there a subtlety for cross region?"
</Person2><Person1> "In real deployments the regional storage endpoint covers the VNet's region and its paired region, and the global storage endpoint extends to all regions. The exam simplifies it by saying no policy means no restriction. Follow the exam's logic, but know that real networks depend on the endpoint type and the storage firewall. Also, a subnet without an endpoint can still reach the storage account over its public endpoint, if the account's firewall allows the VM's public IP, or allows all networks."
</Person1><Person2> "Service endpoint versus private endpoint?"
</Person2><Person1> "Service endpoint: subnet level, the service keeps its public IP, traffic uses the backbone, free, and the service firewall allows subnets, accessible by default from on premises only through the public path. Private endpoint: a private IP in your subnet, resource level, works from on premises over VPN or ExpressRoute, lets you disable public access, supports specific sub resources, has a cost and needs DNS. For the strongest isolation, private endpoint."
</Person1><Person2> "Connectivity services quick tour."
</Person2><Person1> "VPN Gateway: encrypted tunnels over the internet. Site to site connects your on premises network through a local network gateway, which represents your side. Point to site connects individual clients. VNet to VNet connections are possible but peering is usually better. A gateway lives in the GatewaySubnet, route based or policy based, with SKUs, active active, and BGP. ExpressRoute: a private dedicated connection through a connectivity provider, not over the internet, with private peering for VNets and Microsoft peering for Microsoft services. Virtual WAN: a managed hub and spoke at scale. Azure Bastion: RDP and SSH over TLS from the portal, no public IP on the VM, needs AzureBastionSubnet, slash twenty six or larger. NAT Gateway: outbound internet for subnets with static public IPs."
</Person1><Person2> "Load balancing services."
</Person2><Person1> "Pick by layer and scope. Azure Load Balancer, layer four, TCP and UDP, regional, with public and internal flavors, health probes, and the Standard SKU, as the Basic SKU has been retired. Application Gateway, layer seven, HTTP and HTTPS, regional, with URL path routing, multi site hosting, SSL termination, and web application firewall. Traffic Manager, DNS based, global, routing by priority, weighted, performance, geographic, multivalue or subnet. Azure Front Door, layer seven, global, with caching, acceleration and WAF. A global layer four option is the cross region load balancer."
</Person1><Person2> "Network Watcher."
</Person2><Person1> "The diagnostic toolbox. IP flow verify checks whether a packet is allowed or denied by NSG rules for a VM, and tells you which rule. Next hop shows where traffic from a VM goes. Effective security rules and effective routes show the combined result on a NIC. Connection troubleshoot and Connection Monitor test reachability and latency. Packet capture records packets on a VM. Topology draws the network. Flow logs record traffic information, with the newer virtual network flow logs replacing NSG flow logs."
</Person1><Person2> "Summarize."
</Person2><Person1> "Longest prefix wins, then user defined over BGP over system. Virtual appliance is the only next hop needing an IP. To force traffic through a firewall use a user defined route, with IP forwarding on the NVA, not an NSG. NSG priority one hundred to four thousand ninety six, stateful, subnet and NIC both evaluate. Contributor on the NSG controls its rules, not the NIC. ASG groups your own VMs, service tag names Azure services. Service endpoint policy needs the same region and the endpoint on the subnet. No policy means no filtering. Private endpoint gives a private IP. Next episode: compute, virtual machines."
