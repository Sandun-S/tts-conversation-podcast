<Person1> "Welcome back to Study Deep Dive. Episode two: RBAC question drills. In episode one we built the engine. Now we take every RBAC style question in your exam and run it through the three checks: scope, content, plane. For each question I'll tell you what it was testing, why every wrong option is wrong, and how an examiner could twist it."
</Person1><Person2> "Let's go in order. Question one."
</Person2><Person1> "Question one. Developers publish updates to an App Service app using Web Deploy, and must authenticate with their Entra accounts, following least privilege. The options were Owner on the web app, app level FTPS credentials, user level FTPS credentials, or the Website Contributor role."
</Person1><Person2> "What is it testing?"
</Person2><Person1> "Two ideas. First, the difference between publishing credentials and identity based access. FTPS credentials are separate username and password pairs generated by App Service. App level credentials are shared by everyone, user level credentials belong to one deployer. Neither is a Microsoft Entra sign in, so they fail the requirement. Second, least privilege on the role. Owner can delete the app and manage access, far too much. Website Contributor is the built in role designed for managing web apps without managing access to them. Answer: Website Contributor."
</Person1><Person2> "How might they twist it?"
</Person2><Person1> "They might say the developers must only be able to deploy to a staging slot, and ask for the scope to be the slot, or they might add that FTPS must be disabled. You'd still choose the role. The test is whether you spot that Entra authentication means RBAC, not FTPS credentials."
</Person1><Person2> "Now the Jordan and Taylor family. Questions eight, nine and ten."
</Person2><Person1> "Restating the setup. Falcon subscription sits under the management group CorpMG, and contains the resource group rg falcon with webVM. Osprey subscription sits under OpsMG, and contains rg osprey with dbVM and cacheVM. Jordan has Virtual Machine Contributor at CorpMG, and Virtual Machine User Login on the Osprey subscription. Taylor has Virtual Machine Contributor at OpsMG, Virtual Machine User Login on the Falcon subscription, and Virtual Machine User Login on cacheVM."
</Person1><Person2> "Question eight, can Jordan sign in to webVM?"
</Person2><Person1> "Trace it. Is there a login role whose scope contains webVM? Jordan's login role is on the Osprey subscription. webVM is in Falcon. Scope fails. The role Jordan does have over Falcon, VM Contributor, is control plane. Plane fails. False."
</Person1><Person2> "And the twist?"
</Person2><Person1> "If the question had said Jordan can sign in to dbVM, then scope passes, because dbVM is in Osprey, the login role is on the Osprey subscription, and the plane matches since login is a data action. That would be true. The exam can reuse this scenario with many different statements, so always trace again."
</Person1><Person2> "Question nine, can Taylor manage disks and snapshots on webVM?"
</Person2><Person1> "Taylor's management role, VM Contributor, sits at OpsMG. OpsMG contains Osprey, not Falcon. So for webVM there's no management role. Taylor does have a role in Falcon, but it's a login role. Login doesn't include disk or snapshot management. False. Both scope and content fail."
</Person1><Person2> "Question ten, same for cacheVM. I said true."
</Person2><Person1> "Scope passes. cacheVM sits in Osprey, under OpsMG, and Taylor has VM Contributor at OpsMG. Now content. Virtual Machine Contributor lets you manage virtual machines and their attached disks, but the exam says disk snapshots need their own role, such as Disk Snapshot Contributor. So the content check fails. Answer false. And this is the cleanest example in your exam of why checking scope alone is not enough. Many people feel the answer is obvious because the scope is right. But content failed."
</Person1><Person2> "Is that true in real Azure that VM Contributor can't manage snapshots?"
</Person2><Person1> "VM Contributor does not include Microsoft dot Compute slash snapshots actions as a full set, and the exam relies on that. There is a dedicated role named Disk Snapshot Contributor for this. Go with the exam's logic. And remember the memory sentence: VM Contributor manages VMs and disks, but not snapshots, not networking, and not login."
</Person1><Person2> "Also not the virtual network the VM sits in, right?"
</Person2><Person1> "Correct. VM Contributor can create a VM but needs separate join permissions on the network and storage it uses. That is why the custom role in question sixty seven, vmOperatorRole, included networkInterfaces actions and join actions for subnets, public IPs and NSGs. Join actions let you attach those resources to a VM without managing them."
</Person1><Person2> "Next, questions nineteen to twenty two."
</Person2><Person1> "The same scenario, four proposed solutions. The user UserA must be able to list the storage account keys and regenerate them. Proposal one, Storage Account Encryption Scope Contributor. No. That role manages encryption scopes only. Proposal two, Storage Account Key Operator Service Role. Yes. This role exists for exactly this task: it has listKeys and regenerateKey actions, and nothing else. Proposal three, Storage Account Contributor. Yes. It manages storage accounts, including keys. Proposal four, Reader and Data Access. No. It can list keys, which is how it gives data access, but it cannot regenerate them."
</Person1><Person2> "You'd mentioned I got nineteen wrong."
</Person2><Person1> "You said yes to the Encryption Scope Contributor. The trap is the word encryption, which sounds related to keys. But encryption scopes are about which key encrypts which blob container, not about the account access keys. This is pattern two in your mistakes: a feature that sounds related but isn't the fix."
</Person1><Person2> "Is there a way to tell Reader and Data Access apart quickly?"
</Person2><Person1> "Think of it as Reader plus the ability to list keys. It can read, it can fetch a key. It cannot create, modify, or rotate anything. If the requirement contains regenerate, create, write, delete, then Reader and Data Access fails."
</Person1><Person2> "Questions thirty three to thirty five."
</Person2><Person1> "The tenant has three subscriptions. NovaSub sits directly under the tenant root group. AtlasSub sits under Global MG one. ZenithSub sits under Global MG two. Resource groups: rg data in NovaSub holds storage account storeA1. rg app in AtlasSub holds a web app. rg vm in ZenithSub holds vm prod one. Morgan has Contributor at Global MG two. Riley has Storage Account Contributor at storeA1 only. Casey has User Access Administrator at the tenant root group."
</Person1><Person2> "Question thirty three, Morgan resizing vm prod one."
</Person2><Person1> "Scope passes because Global MG two contains ZenithSub, which contains rg vm, which contains vm prod one. Content passes, Contributor includes the VM write action that a resize needs. True."
</Person1><Person2> "Question thirty four, Riley creating a new storage account in rg data. I said true."
</Person2><Person1> "Riley's role is on one resource, storeA1. Creating a new storage account is a write on the resource group, because the new account doesn't exist yet and is created inside the group. A role on one resource cannot create siblings. Scope fails. False. Remember: to create something new, you need the role at the container where it will live, the resource group or higher."
</Person1><Person2> "Question thirty five, Casey assigning Owner to Morgan on rg vm."
</Person2><Person1> "Casey has User Access Administrator at the tenant root group. The tenant root group sits at the top, so everything is below it, including rg vm. User Access Administrator includes role assignment write. True. Note that Casey doesn't need to be Owner herself to assign Owner. User Access Administrator can assign any role, which is why it's considered a highly privileged role, and why the newer RBAC Administrator with conditions exists to narrow it."
</Person1><Person2> "Is there any restriction on assigning a more powerful role than you have?"
</Person2><Person1> "User Access Administrator can assign Owner, even though it is not Owner itself. That's a known privilege escalation path. Which is why privileged roles should be limited, time bound with PIM, and why delegation conditions on RBAC Administrator help."
</Person1><Person2> "Next, the private DNS link. Questions fifty nine and sixty."
</Person2><Person1> "Carlos Vega must link a private DNS zone named corezone1 dot com to a virtual network named NetVnet1. The case study requires least privilege and permissions only at the scope actually required. Question fifty nine: which roles? Network Contributor and Private DNS Zone Contributor. Why both? Creating a virtual network link is an operation on the DNS zone, so you need rights in the zone, Private DNS Zone Contributor. But the link needs to join to a virtual network, which requires the action Microsoft dot Network slash virtualNetworks slash join slash action on that network, and Network Contributor includes it. Network Contributor alone can't write to the DNS zone. Private DNS Zone Contributor alone can't join the network. Contributor is too broad."
</Person1><Person2> "And question sixty, the scope."
</Person2><Person1> "The two resources directly, NetVnet1 and corezone1 dot com. You chose the resource groups, CoreRG2 and CoreRG3. That gives Carlos rights on everything else in those groups, which breaks the least privilege requirement stated in the case study. Also notice the two single options were each incomplete, because the work touches both resources. The pattern: when a task touches two resources, you need rights on both, and the narrowest scope is the resource itself."
</Person1><Person2> "Questions sixty four to sixty six, back to Priya and the network security group."
</Person2><Person1> "Facts. Priya has Contributor on the NSG nsg web zero one, Reader at the subscription, and Storage Account Contributor on the resource group rg network. The NSG is associated with a network interface nic web zero one. Question sixty four, can she create a storage account in rg network? Yes, Storage Account Contributor at the resource group. Question sixty six, can she add an NSG rule blocking a range of source IPs? Yes, Contributor on the NSG includes security rule write, and the rule applies to the associated NIC. Question sixty five, can she modify the DNS settings of nic web zero one? No."
</Person1><Person2> "Why not? The NSG is attached to the NIC."
</Person2><Person1> "Association is not inheritance. RBAC inheritance follows only the Azure resource hierarchy: management group to subscription to resource group to resource. A network interface is not a child resource of an NSG, it is a peer resource that has a reference to the NSG. So Contributor on the NSG gives Priya zero rights over the NIC. And her other roles don't help: Reader is read only, Storage Account Contributor is for storage. Memory sentence: association is not inheritance."
</Person1><Person2> "What would have made it true?"
</Person2><Person1> "Contributor or Network Contributor on the NIC, on rg network, or above. Or if the DNS setting were on the NSG, which it's not."
</Person1><Person2> "Now seventy three and seventy four."
</Person2><Person1> "CorpSub1 with Priya and Sam. Priya must view data in any storage account. Sam must assign users the Contributor role for storage accounts. Least privilege. Priya's options included Owner, Contributor, Reader and Data Access, Storage Account Contributor, User Access Administrator and Storage Blob Data Reader. The answer was Reader and Data Access. You chose Storage Account Contributor, which manages the account but isn't the designed role for viewing data. Storage Blob Data Reader was wrong because it covers only blobs, while the requirement said data in any storage account, and the exam treats that as all the storage services."
</Person1><Person2> "And Sam?"
</Person2><Person1> "Role Based Access Control Administrator. Owner would work but is excessive. User Access Administrator would work but has broader access management rights. RBAC Administrator is narrower, and you can add a condition so Sam can assign only the Contributor role. Contributor and Storage Account Contributor can't assign roles at all. Reader and Data Access can't either."
</Person1><Person2> "Questions seventy eight to eighty."
</Person2><Person1> "Facts. Three subscriptions in one tenant. MG one holds Sub1 and Sub2. Sub1 has RG1 with five Azure Functions. Assignments at MG one: Group1 has Reader, User1 has User Access Administrator. User1 is also Virtual Machine Contributor on Sub1 and Sub2, and Contributor on RG1. User1 is a member of Group1."
</Person1><Person2> "Question seventy eight, can Group1 members view the Azure Functions config?"
</Person2><Person1> "Reader at MG one flows to Sub1, RG1 and the functions. True."
</Person1><Person2> "Seventy nine, can User1 assign Owner for RG1?"
</Person2><Person1> "User Access Administrator at MG one flows down to RG1. True. The other roles are irrelevant. This question teaches that you should look for the one assignment that does the job and ignore the noise."
</Person1><Person2> "Eighty, can User1 create a new resource group and deploy a VM into it?"
</Person2><Person1> "Creating a resource group is a write at the subscription scope. User1's subscription level roles are VM Contributor, which doesn't include resource group write, and the management group level roles are Reader for the group and User Access Administrator, which can't create resources. The Contributor role is only on RG1. Notice that the exam says Contributor at the subscription or Owner is needed. User1 has neither. False. Also, even if User1 could create the group, the question is about using it. So again, find the scope that contains the new thing."
</Person1><Person2> "Let me try a twist. If User1 had Contributor on Sub1, would eighty be true?"
</Person2><Person1> "Yes. Contributor at the subscription includes resource group write and VM write."
</Person1><Person2> "That's a lot of questions. Give me a pattern list."
</Person2><Person1> "One, the answer is often decided by one assignment. Find it. Two, check whether the assignment scope contains the resource. Three, check whether the role contains the action. Four, check the plane. Five, for creation, scope must be the parent. Six, association is not inheritance. Seven, least privilege picks the narrowest role and scope. Eight, only Owner, User Access Administrator, and RBAC Administrator can assign roles."
