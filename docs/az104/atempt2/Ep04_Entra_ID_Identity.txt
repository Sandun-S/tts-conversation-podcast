<Person1> "Welcome back to Study Deep Dive. Episode four: Microsoft Entra ID. This covers questions thirty two, thirty eight, thirty nine, forty five, forty nine, fifty, fifty one and seventy two, and a lot of background that the exam assumes you know. The identity half of the AZ one oh four objective is called manage Azure identities and governance, and Entra ID is the heart of identities."
</Person1><Person2> "Start with the basics. What is Entra ID?"
</Person2><Person1> "Microsoft Entra ID, formerly Azure Active Directory, is the cloud identity service. A tenant is a dedicated instance of Entra ID, with its own users, groups, applications, and domain names. Your default domain ends in onmicrosoft dot com, and you can add custom domains after verifying DNS records. A tenant can be associated with many subscriptions, but a subscription trusts exactly one tenant. That is why moving a subscription to another tenant is a special operation."
</Person1><Person2> "Which objects live in a tenant?"
</Person2><Person1> "Users, either members or guests. Groups, either security groups or Microsoft 365 groups. Devices. Applications and service principals. Administrative units. Roles. Security group membership can be assigned, where you pick members, or dynamic, where rules based on user attributes add and remove members automatically. Dynamic groups require a paid license, Entra ID P1."
</Person1><Person2> "And guests?"
</Person2><Person1> "B two B collaboration lets you invite external users, who appear as guest users using their own identity from another organization or even a personal account. Guests can be given roles and group memberships like members."
</Person1><Person2> "Let's cover the license tiers, because question thirty eight depends on them."
</Person2><Person1> "Four editions. Free, included with Azure and Microsoft 365 subscriptions, gives you user and group management, basic reports, and single sign on to a limited number of apps. Office 365 apps include some features. Premium P1 adds dynamic groups, conditional access, group based licensing, self service password reset with writeback, and hybrid identity features. Premium P2 adds Privileged Identity Management and Identity Protection. And there is Entra ID Governance as an add on for access reviews and entitlement management."
</Person1><Person2> "Question thirty eight."
</Person2><Person1> "A tenant on the Entra ID Free tier, a Fabric license purchased, three identities: a user, a security group, and a Microsoft 365 group. Which can be assigned the license? The user only. Group based licensing is a P1 feature. You assign a license to a group, and Entra automatically gives it to every member. On the Free tier you can only assign licenses directly to individual users. Both group types fail. The wrong options mixed users with one or both of the groups."
</Person1><Person2> "How could the question be twisted?"
</Person2><Person1> "They might say the tenant has P1. Then user and security group and also Microsoft 365 group would be valid, though a security group is the classic license group. Another twist: an unlicensed user can't use the product, even with the group. And licensing requires the user to have a usage location set. Without it, assignment fails."
</Person1><Person2> "Question thirty nine, self service password reset."
</Person2><Person1> "You enable SSPR in the portal, for which identities? The security group and the Microsoft 365 group, not a single user. SSPR has three scope settings: None, Selected, and All. Selected lets you pick a group, and everyone in that group is in scope. You cannot pick an individual user. If you need exactly one user, put them in a group. Users who are in scope must register authentication methods, like phone, email or the authenticator app, and you can require one or two methods to reset."
</Person1><Person2> "Anything about writeback?"
</Person2><Person1> "Password writeback sends the new password back to on premises Active Directory, so hybrid users can reset in the cloud. It requires Entra Connect and P1. Cloud only users don't need writeback."
</Person1><Person2> "Question thirty two, the group naming policy."
</Person2><Person1> "Whenever a Microsoft 365 group is created, the name must automatically become office first, then the requested name. The answer sequence was: create a group naming policy, set Add prefix to Attribute, and set Select type to Office. Let's pick apart the options. Prefix versus suffix: office comes first, so prefix. String versus attribute: a string is a fixed text, like the same word on every group. An attribute is taken from the creator's profile, like Office, Department, Company, Country, State or Title. We want the creator's office, so attribute. The wrong options included suffix versions, string versions, and customizing company branding, which has nothing to do with naming."
</Person1><Person2> "Where do you configure it?"
</Person2><Person1> "In the Entra admin center, under Groups, then Naming policy. A naming policy has two parts: the prefix and suffix structure, and a list of blocked words. It applies to Microsoft 365 groups, in all the workloads that create them, like Teams, Outlook, Planner. It requires the right license for the users creating groups. Some administrator roles are exempt from the policy so they can still name groups as they want. And remember it applies at creation or rename, not retroactively to existing names, though updates can enforce on renames."
</Person1><Person2> "Now custom security attributes. Questions forty nine, fifty, fifty one, seventy two."
</Person2><Person1> "What are they? Custom security attributes are business specific key value pairs that you define in Entra and assign to objects, for example Project equals Baker, or Cost center equals one two three. They aren't visible to everyone, they're protected, and they can be used for fine grained access control, such as attribute based conditions in RBAC, where a principal's attribute is compared with a resource tag or attribute."
</Person1><Person2> "Where can they be assigned?"
</Person2><Person1> "To three kinds of objects: users, service principals which means enterprise applications, and managed identities. They cannot be assigned to groups, any kind of group. Not security groups, Microsoft 365 groups, or mail enabled security groups. Question seventy two: Attr1 defined, a user, a security group and a service principal, which identities can get it? User and service principal. Question forty nine and fifty one both pointed at group objects, Cohort1 and Cohort2, so the answer was false for each, no matter who was assigning."
</Person1><Person2> "Take question forty nine step by step."
</Person2><Person1> "The case study says implementing the planned change for AttribTag1 is required. Priya Shah assigning AttribTag1 to Cohort1. Cohort1 is a group. Groups aren't supported targets. So false, regardless of what role Priya has. The explanation also notes that Priya is a Global Administrator, and that Global Administrators don't automatically have rights to read, define or assign custom security attributes. But the question dies on the object type first. You said true. The reasoning trap: she's a Global Admin, so she can do anything. Not here, for two separate reasons."
</Person1><Person2> "Question fifty."
</Person2><Person1> "Derek Nguyen has the Attribute Definition Administrator role, and the question asks whether he can assign AttribTag1 to Carlos Vega, a user. Carlos is a valid target, so the object type passes. But the role doesn't. Attribute Definition Administrator can create and manage attribute sets and attribute definitions. Assigning values to objects needs Attribute Assignment Administrator. False. Define is not assign."
</Person1><Person2> "Question fifty one."
</Person2><Person1> "Lena Osei has the Attribute Assignment Administrator role. That is the right role, so people say true. But she is assigning to Cohort2, a group. False. In this question the role was right and the object type was wrong. In question fifty the object type was right and the role was wrong. The exam deliberately mirrors the two failure modes. Always check both: role and object."
</Person1><Person2> "What about the other two attribute roles?"
</Person2><Person1> "Attribute Definition Reader and Attribute Assignment Reader can read definitions and assigned values, with no write. Also, these roles can be scoped to an attribute set, so you can delegate a department's attributes to a department administrator without exposing others. And again: Global Administrator, and even Privileged Role Administrator, don't have these permissions by default. You have to assign the specific roles. The reason is that custom security attributes can drive access decisions, so you separate who defines them from who assigns them."
</Person1><Person2> "Why does the exam keep returning to the permission by default?"
</Person2><Person1> "Because it's a counterintuitive fact. People assume Global Administrator is all powerful. In Azure resource land, it isn't, and in custom security attributes, it isn't either."
</Person1><Person2> "Now question forty five again, because it's an Entra versus Azure trap."
</Person2><Person1> "The wrong option said none of the users can create a subnet because subnet creation requires Global Administrator in Entra. That is false. Subnets are Azure resources, authorized by Azure RBAC. Entra roles don't matter. This tells you how the exam writes distractors: mixing planes. Use the sentence: Entra roles manage identities and directory objects. Azure roles manage Azure resources. They don't overlap, except when someone elevates access."
</Person1><Person2> "More Entra topics the exam likes?"
</Person2><Person1> "Several quick ones. Multifactor authentication and conditional access, which needs P1, decides which sign ins need extra proof, based on user, device, location and risk. Privileged Identity Management, P2, makes role assignments eligible and time bound, with approval and justification. Access reviews recertify group memberships. Administrative units delegate user management for a subset of users. Entra Connect synchronizes on premises Active Directory with Entra, using password hash sync, pass through authentication, or federation. Entra Domain Services provides managed domain services, like LDAP and Kerberos, for lift and shift applications. Device identity: registered, joined, or hybrid joined."
</Person1><Person2> "Which Entra built in roles should I know?"
</Person2><Person1> "Global Administrator, with everything. User Administrator, managing users and groups, resetting passwords for non admins. Groups Administrator. License Administrator, assigning licenses. Authentication Administrator, resetting auth methods for non admin users. Security Administrator and Security Reader. Application Administrator. Billing Administrator. And the attribute roles. Remember: roles that start with Attribute are the custom security attribute roles."
</Person1><Person2> "Let me test: a user needs to assign licenses but nothing else. Which role?"
</Person2><Person1> "License Administrator, from the Entra roles list, not an Azure RBAC role."
</Person1><Person2> "And a user needs to manage group membership only for groups?"
</Person2><Person1> "Groups Administrator. Not User Administrator, which is broader."
</Person1><Person2> "Summarize episode four."
</Person2><Person1> "Entra roles manage identities, Azure roles manage resources. Free tier licensing is per user, group licensing is P1. SSPR scope is None, Selected group, or All, never a single user. Group naming policy: prefix versus suffix, string versus attribute, applies to Microsoft 365 groups. Custom security attributes go on users, service principals and managed identities, never groups. Definition administrator defines, assignment administrator assigns, and Global Administrator has neither by default. In the next episode we cover governance: Azure Policy, management groups, tags, locks and moving resources."
