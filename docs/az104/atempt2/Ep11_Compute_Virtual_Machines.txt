<Person1> "Welcome back to Study Deep Dive. Episode eleven: virtual machines. Maintenance and redeploy, availability, scale sets, sizing and disks, extensions, and Desired State Configuration. This covers questions twenty three to twenty eight and seventy one, and ties together disk encryption and backup from other episodes."
</Person1><Person2> "Start with how a VM is built."
</Person2><Person1> "A VM is a compute resource, plus attached resources: an OS disk, optional data disks, a network interface, a public IP optionally, and sits in a VNet subnet. Size defines vCPU, memory, and limits. The size families: B series burstable, D series general purpose, E series memory optimized, F series compute optimized, N series GPU, L series storage optimized, M series large memory. A VM is billed per second while it's allocated. Power states matter. Stopped from inside the OS leaves the VM allocated, so you still pay for compute. Stopped, deallocated, from the portal or CLI, releases the compute, so you stop paying for compute but still pay for disks. Deallocation also releases dynamic public IPs, while static ones stay."
</Person1><Person2> "Why do people deallocate?"
</Person2><Person1> "To save money, and to resize to sizes that aren't available on the current hardware cluster. In question seventy one, the exhibit showed ShireenVM as stopped, deallocated."
</Person1><Person2> "Question seventy one."
</Person2><Person1> "You must enable Desired State Configuration for the VM. What's the first action? Power on the VM. The explanation: DSC is delivered through a VM extension, and extensions execute inside the running guest operating system. A deallocated VM has no running OS, so nothing can be configured. The other options: assigning a DNS name is about naming, connecting requires a running VM too, capturing a snapshot is about backup. Pattern: when a prerequisite is unmet, the first step is to satisfy it."
</Person1><Person2> "Explain extensions and DSC."
</Person2><Person1> "VM extensions are small agents that run post deployment tasks: the Custom Script Extension runs scripts, the Azure Monitor Agent collects telemetry, the Entra login extensions allow Entra sign in, the antimalware extension, the DSC extension and others. Extensions are installed via ARM, portal, CLI or PowerShell, and they need the VM agent, which is installed by default on Marketplace images, and a running VM."
</Person1><Person2> "And DSC?"
</Person2><Person1> "Desired State Configuration is a PowerShell declarative approach: you write a configuration describing the desired state, like IIS installed, a file present, a service running. A node applies the configuration, with the Local Configuration Manager, and can correct drift. In Azure, you could push a configuration through the DSC extension, or use Azure Automation State Configuration as a pull server, onboarding nodes. Microsoft is steering new work toward Azure Machine Configuration and Azure Policy guest configuration, but the classic DSC extension still appears in questions."
</Person1><Person2> "Now the maintenance scenario, questions twenty three to twenty eight."
</Person2><Person1> "The six questions repeat one scenario with different proposed solutions. ShireenVM, deployed using a custom ARM template named deployVM dot json, will be affected by a scheduled platform maintenance event. You must immediately relocate it to another host. Proposals. One, Updates blade, One time update: no. Two, Overview blade, move to another subscription: no. Three, Move to a different resource group from the Overview blade: no. Four, Updates blade, click Enable: no. Five, Redeploy plus reapply blade, click Redeploy: yes. Six, move to another resource group from the resource group blade: no."
</Person1><Person2> "Why does redeploy work?"
</Person2><Person1> "Redeploy shuts the VM down, migrates it to a new node in the same Azure region, and powers it back on. The OS disk and data disks are preserved. The temporary disk contents are lost. Dynamic IPs may change, static IPs and the configuration are preserved. Use cases: platform maintenance, connectivity issues, RDP failures. You can also run it with az vm redeploy, or Set AzVM with the Redeploy switch."
</Person1><Person2> "And the others?"
</Person2><Person1> "Moving between resource groups or subscriptions only changes the ARM metadata, the resource ID and the billing association, not the host the VM runs on. The Updates blade belongs to Azure Update Manager: One time update installs operating system patches, and Enable turns on periodic assessment and patching. They manage guest OS updates, not the Azure host maintenance event. The custom template detail is irrelevant, like the Owner detail in the DNS question."
</Person1><Person2> "What is the difference between platform maintenance and guest patching?"
</Person2><Person1> "Platform maintenance is Azure updating the host: hypervisor, firmware, networking. Most of that is memory preserving, with a pause of a few seconds, or non rebootless with a reboot you can pre empt. Azure sends a scheduled event, visible in the portal, in the Azure Resource Health and Service Health, and inside the VM via the Instance Metadata Service Scheduled Events endpoint, which gives apps time to react. For some dedicated hosts or isolated sizes, you can use maintenance configurations to control the window. Guest patching is operating system updates inside the VM, done by Azure Update Manager, WSUS or Linux package managers."
</Person1><Person2> "And Reapply?"
</Person2><Person1> "Reapply re applies the VM's goal state, used when a VM is stuck in a failed provisioning state, for example after a failed extension or a transient fabric issue. It doesn't relocate the VM. It sits next to Redeploy on the same blade, which is why the exam named the blade Redeploy plus reapply."
</Person1><Person2> "Availability. What are the options?"
</Person2><Person1> "Single VM with premium SSD or ultra disks: ninety nine point nine percent SLA. Availability set: spreads VMs across fault domains, which are separate racks sharing power and network, and update domains, which are groups rebooted together during maintenance. Ninety nine point nine five percent SLA. Availability zones: separate datacenters within a region, each with independent power, cooling and networking, ninety nine point nine nine percent SLA for two or more VMs in different zones. Availability set membership is chosen at creation. A VM can't be in both a set and a zone. Zone redundant services like ZRS storage and zone redundant load balancers complement zones. Region pairs and Site Recovery give disaster recovery across regions."
</Person1><Person2> "Scale sets."
</Person2><Person1> "A Virtual Machine Scale Set manages a group of VMs from a common model, scaling in and out automatically, with autoscale rules on metrics like CPU or on a schedule, with minimum, maximum and default instance counts, and a scale in policy. Orchestration modes: Flexible, the modern default, which lets you mix VM sizes, spread across zones and fault domains, and manage instances as regular VMs; and Uniform, identical instances managed as a unit. A load balancer or application gateway distributes traffic to instances. Upgrade policies: automatic, rolling, or manual, control how instances get a new model."
</Person1><Person2> "Disks."
</Person2><Person1> "Three disk roles: the OS disk, data disks, and the temporary disk, local to the host, used for page files and scratch data, lost on redeploy, resize to a different host, and stop deallocate. Managed disk types: Standard HDD, Standard SSD, Premium SSD, Premium SSD v2, and Ultra Disk. Disks are redundant locally or across zones. Snapshots are point in time read only copies, can be full or incremental, used to create new disks. Images capture a generalized VM, and Azure Compute Gallery stores and replicates images and versions across regions. Ephemeral OS disks store the OS on the VM's local cache or temp storage, with fast reimage and no storage cost, but state is lost on deallocate, and they aren't supported by ADE, as you saw."
</Person1><Person2> "Resizing."
</Person2><Person1> "You can resize from the Size blade. If the new size is available in the current hardware cluster, the VM restarts. If not, you must deallocate first, so the VM can move to a cluster that has the size. Resizing changes the temp disk and may change the number of NICs and disks allowed. Dynamic IPs may change after deallocation."
</Person1><Person2> "How do networking and VMs connect in the exam?"
</Person2><Person1> "A VM needs a NIC, with a private IP from its subnet, static or dynamic. A public IP is optional. Accelerated networking improves throughput. The NIC DNS setting overrides VNet DNS. NSGs attach to the NIC or subnet. Bastion for management. And as you saw in the RBAC episode, VM Contributor can manage VMs but needs join permissions on network resources, and doesn't include login or snapshot rights."
</Person1><Person2> "Entra sign in for VMs."
</Person2><Person1> "Install the AADLoginForWindows or AADSSHLoginForLinux extension, enable a system assigned managed identity, and assign the user Virtual Machine User Login for a standard session, or Virtual Machine Administrator Login for admin rights, at the VM, resource group, or subscription scope. That's the data plane from questions eight to ten, and the dataActions you add to a custom role in question sixty seven."
</Person1><Person2> "Backup for VMs."
</Person2><Person1> "Covered in episode thirteen, but remember the vault must be in the same region as the VM, and a VM backup snapshots all its disks."
</Person1><Person2> "Give me twists for this episode."
</Person2><Person1> "Replace Redeploy with Reapply, wrong. Ask which preserves the temp disk, none. Ask which operation changes the physical host without downtime, there's none; redeploy has downtime. Ask what happens to a dynamic public IP after deallocation, it may change. Ask for the first step before installing an extension, make sure the VM is running. Ask which availability option protects against a datacenter failure, zones. Ask which protects against rack failure but within one datacenter, availability set."
</Person1><Person2> "Summarize."
</Person2><Person1> "Redeploy moves the host, same region, keeps OS and data disks, loses the temp disk. Moving subscriptions or resource groups is metadata only. Update Manager is for guest patching. Extensions and DSC need a running VM. Deallocated stops compute billing, stopped in the OS does not. Availability: single VM, set, zone, by SLA. Scale sets scale automatically. Ephemeral OS disks, Write Accelerator and dynamic volumes block ADE. Next episode: containers and App Service."
