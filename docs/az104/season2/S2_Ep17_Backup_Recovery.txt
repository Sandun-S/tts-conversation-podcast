</Person1><Person2> "Now retention, questions forty five and forty six."
</Person2><Person1> "A backup policy for a VM has a schedule and retention settings. Retention has four tiers in a grandfather father son scheme: daily backup points retained for a number of days, here thirty. Weekly points, taken on a chosen weekday, retained for a number of weeks, here ten. Monthly points, from either a specific day of month or a week of the month, such as the first Sunday, retained for a number of months, here thirty six. Yearly points, from a chosen month and week or day, retained for a number of years, here ten, in March. Question forty five: the backup that occurs on Sunday, March first, will be retained for how long? Options: thirty days, ten weeks, thirty six months, ten years. Answer: ten years. Question forty six: the backup on Sunday, November first: answer thirty six months. Both right."
</Person1><Person2> "Explain the logic of which one wins."
</Person2><Person1> "A single backup run can qualify for several retention tiers. The backup on Sunday March first is a daily backup, it's a Sunday so it's also the weekly one, it's the first Sunday of the month so it's the monthly one, and March is the yearly month, so it's also the yearly one. Azure keeps the recovery point for the longest of the applicable retention periods: so ten years. On Sunday November first: daily yes, weekly yes because it's Sunday, monthly yes if the monthly point is first Sunday, yearly no because the yearly point is March. So thirty days, ten weeks, thirty six months apply, and the longest is thirty six months. Rule: when a point matches multiple tiers, the longest retention wins. Always enumerate which tiers each date qualifies for, then take the max."
</Person1><Person2> "Twist example?"
</Person2><Person1> "A backup on a Tuesday in the middle of April qualifies only for daily, so thirty days. A backup on Sunday, April fifteenth, not first Sunday, qualifies for daily and weekly, so ten weeks, which is about seventy days. A backup on Sunday, January fourth: first Sunday, so thirty six months. Beware of the question's wording on the policy: if the monthly rule is by day of month, such as the first day, not the first Sunday, you must check the date, not the weekday."

Remember the first run starts at the scheduled time, not at enable time, unless you trigger a backup now."

</Person1><Person2> "Why not restore the whole VM?"
</Person2><Person1> "Restoring the VM, or the disks, would take far longer and is overkill for two files. File recovery, also called item level restore, mounts the recovery point as a drive on a machine, so you browse and copy just the files. The process: in the vault's backup items, select the VM, click File Recovery. Choose the recovery point from a date before the deletion. Download the executable for Windows or script for Linux. Run it on the machine where you want the files, with the password shown in the portal. The script connects to the recovery point using iSCSI and mounts the volumes as drives or folders, valid for twelve hours. Browse, copy the files, then unmount. Copying with AzCopy is possible but unnecessary, since the files are on a mounted drive. Mount a VHD is a different approach, used with restored disks."
