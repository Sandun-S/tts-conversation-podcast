</Person1><Person2> "Explain the structure of a DCR."
</Person2><Person1> "A data collection rule is a set of instructions for the Azure Monitor agent. It has three parts. Data sources: what to collect from the machine, like Windows event logs, Syslog, performance counters, text logs. Destinations: where to send the data, a Log Analytics workspace, and in newer versions Azure Monitor metrics and others. Data flows: link streams to destinations, with optional transformations. You assign the rule to machines using data collection rule associations. The machines are the sources, hosting the agent. A storage account is not a collection source for a DCR, since DCRs are agent configuration for machines. SQL Database has its own diagnostic settings, not DCRs. A workspace is a destination, not something you collect from. As a destination, per the exam, only the Log Analytics workspace is valid. In real Azure, newer DCR types allow other destinations like Event Hubs and storage blobs, for specific scenarios. For this exam, choose the workspace."

</Person2><Person1> "By default, agents send data to Azure Monitor endpoints over the public internet. For private connectivity, you use Azure Private Link, but Azure Monitor is a family of services with many endpoints: the workspace ingestion and query endpoints, data collection endpoints, Application Insights, and so on. </Person1><Person2> "Now alerts, questions fifty five to fifty seven."
</Person2><Person1> "Let me first lay out the alert model. An alert rule defines what to watch, the scope, the condition and the actions. Types: metric alerts, log search alerts, activity log alerts, Service Health alerts, and so on. When the condition is met, an alert fires, creating an alert instance that you can see in the Alerts blade of Azure Monitor, with states New, Acknowledged and Closed. The rule can invoke one or more action groups, which perform notifications or actions. Then there's the alert processing rule, formerly action rules, which acts on fired alerts, after they're generated and before the actions execute. A processing rule can suppress notifications, for example during maintenance windows, or add action groups to alerts at a scope. It has a scope, a filter, a schedule or always, and a rule type."
</Person1><Person2> "What does suppress notifications actually suppress?"
</Person2><Person1> "Only the notifications and actions of the action groups. The alert itself still fires and is recorded. So you still see the alert in the portal, you just don't get an email, or a webhook call. That detail answers question fifty five."
