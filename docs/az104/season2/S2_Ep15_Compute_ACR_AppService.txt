You have AppServicePlanA on the Standard tier, and you want it to automatically increase its instance count whenever CPU utilization exceeds eighty percent. Which setting? Answer: rule based scaling in the Scale out settings. You got it right. Two directions of scaling. Scale up, vertical: change the plan to a bigger tier or size, more CPU and memory per instance, for example Standard S one to Premium P one. Scale out, horizontal: change the number of instances. And scale out has three modes. Manual: you set a fixed instance count. Rule based, also called autoscale: you define rules and schedules, like if average CPU is over eighty percent for ten minutes, add one instance, with a minimum, maximum and default count. Automatic scaling: a newer, platform managed mode on Premium plans, where App Service scales for you based on HTTP load, with pre warmed instances, and you can't define rules like a CPU threshold."
</Person1><Person2> "So why is it rule based?"
</Person2><Person1> "Because the requirement names a condition: CPU over eighty percent. Only rule based scaling lets you define a metric threshold. Automatic scaling is intelligent but has no custom thresholds, and also isn't available on Standard. Manual needs you to click. Selecting Premium P one or Standard S one under Scale up changes the size of the instances but doesn't add instances. Also note which tiers support autoscale: Standard and above. Basic supports manual scale only, up to three instances. Free and Shared don't scale out."

</Person1><Person2> "What's a dedicated data endpoint?"
</Person2><Person1> "When you pull an image from a registry, two kinds of requests happen. Control plane or registry requests go to the registry's login server, like contoso twenty twenty three dot azurecr dot io. Data requests download the image layers, which are stored in Azure Storage managed by the registry, and by default they come from a shared wildcard endpoint like star dot blob dot core dot windows dot net. If you have strict firewall rules, allowing a wildcard storage domain is too broad: it permits access to any storage account, including an attacker's. With dedicated data endpoints, the registry exposes regional endpoints with the format registry name dot region dot data dot azurecr dot io. You allow only those names in the firewall. It's available only in the Premium tier. Enabling it is a setting on the registry."
</Person1><Person2> "What does ACR's data endpoint have to do with private endpoints?"
</Person2><Person1> "With a private endpoint on a Premium registry, the registry gets private IPs for both the login server and the data endpoint, so image pulls stay inside the virtual network. With dedicated data endpoints enabled, each region has its own endpoint, and replicated regions get theirs. If you're not using private endpoints and just a firewall, dedicated data endpoints let you write narrow rules."
