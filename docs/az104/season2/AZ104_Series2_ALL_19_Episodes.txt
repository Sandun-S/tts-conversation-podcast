</Person1><Person2> "Start at the very beginning. What is Active Directory?"
</Person2><Person1> "Imagine a company with an office building. In the building there are computers, file servers and employees. Someone has to keep the master list of who is allowed to do what: this person is Anna in finance, her password is this, she may open that share, she may log in to those computers. In the nineties Microsoft built a product for that master list, called Active Directory Domain Services, usually shortened to AD DS. It runs on Windows Server machines called domain controllers. A domain controller holds the directory, the database of accounts, and answers every login on the local network."
</Person1><Person2> "So AD DS is a server role, an on premises database of identities."
</Person2><Person1> "Exactly. And it has a particular structure. Learn four words. A domain is a boundary containing accounts and computers, for example ironclad dot com. A forest is the top level container, one or more domains that share a schema and trust each other. In the Ironclad case study the company has an Active Directory forest named ironclad dot com. An organizational unit, an OU, is a folder inside a domain, used to organize accounts and apply policies, for example OU Finance, OU Engineering. And objects are the things in the folders: users, groups, computers."
</Person1><Person2> "Why do the OUs matter for Azure?"
</Person2><Person1> "Because later, when you synchronize to the cloud, you choose which folders to synchronize. In your Azure Files question the setup was: User one in OU two, User two in OU one, Group one in OU one, and the synchronization only covers OU one. Kerberos works with tickets: you log in once, the domain controller hands you a ticket granting ticket, and you use it to request tickets for each service, like a file server. The ticket contains your identity and your group memberships, as security identifiers, SIDs. Remember that detail, we use it in the Azure Files episode."
</Person1><Person2> "Fine. Now what is Microsoft Entra ID, and how is it different?"
</Person2><Person1> "Microsoft Entra ID, formerly Azure Active Directory, is a completely different product that unfortunately shares the old name. It is a cloud identity service for the internet. It does not use Kerberos or OUs or domain controllers. It uses web protocols: OAuth two, OpenID Connect and SAML. Tokens instead of tickets. Its structure is flat: one tenant, one directory, no OUs. A tenant is your organization's dedicated instance, like ironclad dot onmicrosoft dot com, and it holds users, groups, applications and devices. Every Azure subscription trusts exactly one tenant, and RBAC role assignments use identities from that tenant."
</Person1><Person2> "If someone says Azure AD is Active Directory in the cloud, is that wrong?"
</Person2><Person1> "It's the most common misunderstanding. Entra ID is not a domain controller in the cloud. It cannot do Kerberos for file servers, it cannot apply Group Policy, it has no domain join in the old sense. It is an identity provider for modern cloud and web applications. If you need the old style, managed in the cloud, there is a third product, Microsoft Entra Domain Services, which gives you managed domain controllers in a virtual network, so legacy apps can use Kerberos, LDAP and domain join without you running servers. Three things: AD DS on premises, Entra ID in the cloud, Entra Domain Services as managed AD DS in Azure."
</Person1><Person2> "Okay. So how does a company with AD DS get into the cloud?"
</Person2><Person1> "Hybrid identity. The idea is that the same human has one identity, with one username and password, in both worlds. You don't want Anna to have two accounts. The classic tool is Microsoft Entra Connect, the Sync version. You install it on an on premises server. It reads from AD DS, and it writes to Entra ID. By default it runs a delta sync about every thirty minutes. The copies in Entra are called synchronized or hybrid users. The newer lighter option is Microsoft Entra Cloud Sync, which uses a small agent, supports multiple disconnected forests, and is managed from the cloud. Both do the same job conceptually."
</Person1><Person2> "What exactly is copied?"

</Person1><Person2> "Next, authentication. How do hybrid users sign in to Azure?"
</Person2><Person1> "Three methods, and this is high value. Method one, password hash synchronization, PHS. Entra ID does not store passwords or hashes. Method three, federation, usually with Active Directory Federation Services, AD FS. Entra ID redirects the sign in to your own federation servers, which authenticate and issue a token back. </Person1><Person2> "What does governance actually mean in Azure?"
</Person2><Person1> "Governance is the set of rules and controls that keep an organization's cloud estate consistent, secure and affordable. Imagine a city. </Person2><Person1> "Azure Policy evaluates resources against rules and either reports or enforces. The pieces. A policy definition is a rule: an if condition and a then effect. </Person2><Person1> "Deny: blocks the request that violates the rule, the resource isn't created or updated. Audit: allows it but records non compliance.
