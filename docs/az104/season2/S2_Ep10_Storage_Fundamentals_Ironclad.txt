</Person1><Person2> "Explain the services first."
</Person2><Person1> "A storage account is a container for Azure Storage data services. Inside it you can have four data services. Blob storage: object storage for unstructured data like documents, images, backups, video, logs. You access it by REST, SDKs, AzCopy, and also with NFS and SFTP if enabled. Azure Files: managed file shares over SMB and NFS, which you mount like a network drive. Queue storage: a message queue for decoupled applications. Table storage: a NoSQL key attribute store for structured data. Plus Azure Disks, which are managed separately as managed disks but built on the same ideas. The case study says nothing about shares mounted on servers, nothing about messages or tables. It says documents into Blob Storage. Hence Blob true, Table false, File false."
</Person1><Person2> "And the Archive tier requirement. Why does it rule out Files?"
</Person2><Person1> "Access tiers are a blob concept. Blob storage has Hot for frequent access, Cool for infrequent, at least thirty days, Cold for rarely accessed, at least ninety days, and Archive for rare access, at least one hundred eighty days, offline. Hot costs more to store and less to access. Archive is the cheapest to store, but blobs in Archive are offline: you can't read them until you rehydrate them to Hot, Cool or Cold, which takes hours, up to fifteen hours for standard priority, or under one hour for high priority on small blobs. Azure Files has its own tiers, transaction optimized, hot, cool, and premium, but no Archive. So the requirement store using the Archive access tier immediately means blobs."
</Person1><Person2> "How do I actually put a blob in the Archive tier?"
</Person2><Person1> "Account level default access tier can only be Hot or Cool. You can't set the account default to Archive. Archive is set per blob, or per blob version or snapshot, either at upload time or by changing the tier later, or automatically through a lifecycle management policy rule, for example move to Archive when not modified for ninety days. Early deletion fees apply if you delete or move a blob before its minimum period: thirty days for Cool, ninety for Cold, one hundred eighty for Archive. Archive isn't available on premium accounts, nor with ZRS, GZRS, or RA-GZRS redundancy for the Archive tier at the account level in some regions. The exam rarely goes that deep."
</Person1><Person2> "Account types and redundancy, quickly."
</Person2><Person1> "Account types: Standard general purpose version two, the default for most scenarios, supports blob, files, queues, tables. Premium block blobs for low latency, Premium file shares, Premium page blobs. Legacy: general purpose version one and BlobStorage accounts, which you should upgrade. Redundancy: locally redundant storage, three copies in one datacenter; zone redundant storage, three copies across availability zones in one region; geo redundant, LRS here plus asynchronous copy to a paired region; geo zone redundant, ZRS in the primary plus LRS in the secondary; plus read access variants. Hierarchical namespace turns an account into Data Lake Storage Gen two, giving real directories, which also matters for the planned changes in series one."
</Person1><Person2> "Now question seventy seven, the transfer."
</Person2><Person1> "You need to migrate the blueprint files to Azure. Options: use the Azure Import Export service; use Azure Storage Explorer to copy the files; generate a shared access signature, map a drive, and copy with File Explorer; generate an access key, map a drive, and copy with File Explorer. Answer: Storage Explorer. You got this one right. You can't map a drive to blob storage, only to Azure Files shares."
</Person1><Person2> "Why is that the logic, and what about the Import Export option?"
</Person2><Person1> "Follow the requirement: transfer by using the internet means online tools, Storage Explorer, AzCopy, the portal upload, Azure Data Factory, Storage Mover. Import Export and Data Box are offline physical shipping, used for huge data or poor bandwidth, and would violate the internet requirement."
</Person1><Person2> "Give me the whole transfer toolbox."
</Person2><Person1> "AzCopy: command line, fast, parallel, supports Entra login or SAS, great for scripts. Storage Explorer: desktop GUI, drag and drop, uses AzCopy under the hood. Azure portal: small uploads. Azure Storage Mover: managed migration service from on premises file shares into Azure Storage. Azure Data Factory: orchestration for large scale copy between data stores. Azure File Sync: syncs on premises Windows file servers with Azure Files. Azure Import Export: you ship your own disks to a datacenter, for large offline data into blobs and files. Azure Data Box: Microsoft ships you a rugged device to fill and send back. SFTP: supported on accounts with hierarchical namespace. Rule: internet equals AzCopy or Storage Explorer, huge data with limited bandwidth equals Data Box or Import Export."
</Person1><Person2> "Why are the map a drive options wrong?"
</Person2><Person1> "Mapping a network drive uses the SMB protocol, which exists for Azure Files. Blob Storage doesn't offer SMB. Also, a shared access signature or access key is an authentication method, not a transfer mechanism, so the combination only makes sense for a file share. Since Ironclad needs blobs in the Archive tier, a mapped drive is the wrong service entirely."
</Person1><Person2> "What about the planned change, organize storage content into directories wherever achievable, from series one?"
</Person2><Person1> "Same idea, only account with hierarchical namespace support real directories, the datastore one case. Not needed here. But keep the hierarchical namespace in mind for Ironclad if a question says engineering folders with permissions: Data Lake Storage Gen two with ACLs."
</Person1><Person2> "Twists on this case study's storage portion?"
</Person2><Person1> "Ask which tier meets the requirement: Archive, set at the blob level. Ask which account type: general purpose version two. Ask which redundancy: not specified, so any is acceptable, the exam would give a requirement like survive a regional outage, which then points to geo redundant. Ask how to give a partner temporary access: shared access signature, which we cover in the next episode. Ask how to protect from deletion: immutability or soft delete.
